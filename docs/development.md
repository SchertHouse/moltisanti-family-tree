# Sviluppo

Richiede Node.js 22+ e npm. Installare con `npm ci`; avviare `npm run dev`; controllare con `npm run lint`, `npm test`, `npm run typecheck`, `npm run build`, `npm run check:dist`. `npm run test:e2e` esegue i flussi browser con Playwright in Chromium, Firefox, WebKit e viewport touch-emulate Chromium/WebKit; prima dell'esecuzione locale installare i browser con `npx playwright install chromium firefox webkit` e le dipendenze di sistema richieste con `npx playwright install-deps chromium firefox webkit` (richiede i permessi del package manager). CI esegue l'intera matrice con `--with-deps`. L'emulazione non sostituisce la verifica su telefoni/tablet fisici. Test di crittografia usano Web Crypto; i test GitHub mockano la rete.

Per una verifica temporanea delle foto su iPhone, entrare in modalità Admin e aprire il test nella scheda di una persona con foto. Il test mostra prima l'originale decifrato in HTML e SVG, poi confronta la variante ridotta dell'albero tramite URL `blob:` e data URL diretto, ritaglio SVG e riferimento legacy `xlink:href`. Se la generazione della variante fallisce, mostra comunque il confronto dell'originale e l'errore restituito dall'elaborazione. Non modifica l'archivio e rilascia gli URL quando viene chiuso; le sorgenti restano in memoria/DOM solo durante il test. Rimuovere il pannello temporaneo dopo la diagnosi.

Per ridimensionare in-place le immagini di un JSON **in chiaro**: `npm run images:resize -- <archivio.json> <larghezza-massima> <altezza-massima>`. Per esempio: `npm run images:resize -- family-archive.json 320 240`. I limiti inseriti non possono superare i massimi in `image-config.json`. `--dry-run` elabora e valida tutte le immagini senza modificare il file. Le foto profilo e tutte le voci `gallery` vengono considerate; si elaborano solo immagini che superano almeno uno dei limiti. Il ritaglio è centrato e segue il rapporto larghezza/altezza richiesto, il ridimensionamento non ingrandisce e le immagini elaborate diventano JPEG usando la qualità in `image-config.json`. Il file originale viene sostituito solo dopo il completamento corretto dell'intera elaborazione, con scrittura atomica. Il JSON in chiaro contiene dati personali: esegui la procedura localmente, proteggi il file e i backup e cifra/pubblica il risultato tramite l'app. Lo script rifiuta l'archivio cifrato, le singole foto cifrate e le immagini animate da modificare; esporta prima il JSON in chiaro dall'app. GIF animate entro i limiti restano inalterate.

Usare componenti piccoli e TypeScript strict; niente stringhe UI nei componenti salvo eccezioni tecniche. La configurazione immagini autorevole è `image-config.json`: input massimo 8 MiB, massimo normalizzato 320 × 320, senza upscaling, JPEG qualità 0.9, varianti albero 128 e scheda 320, due elaborazioni simultanee e cache massima 200 voci/30 MiB. Modificare i limiti in quel file e non duplicarli nel codice. Il cambio di limite vale per i nuovi caricamenti e le normalizzazioni successive, non riscrive in automatico le foto già cifrate negli archivi. Quando una foto è già entro la misura della variante richiesta, il codice la restituisce direttamente senza ridimensionamento né duplicazione nella cache.

Il ritaglio quadrato, orientamento EXIF, rimozione metadati e normalizzazione restano nel browser. Testare geometria, risoluzione, output e migrazione/cifratura per immagine. Le varianti vanno generate on demand, cifrate prima di IndexedDB e riutilizzate solo con passphrase valida; mantenere una cache temporanea limitata per i browser senza IndexedDB. Testare invalidazione delle chiavi al cambio sorgente, errori di decifratura e fallback cache. Rilasciare bitmap e URL temporanei.

Il ricordo della passphrase è opt-in: conservarla solo come ciphertext AES-GCM con `CryptoKey` non esportabile in IndexedDB dedicato, mai in local/session storage o in chiaro. La cache immagini e lo store delle credenziali devono restare separati. Testare roundtrip, ciphertext privo di passphrase in chiaro, rimozione, fallback a inserimento manuale e apertura automatica.

Non usare dati reali nei test. Nessuna chiamata API esterna o commit nei test. Le traduzioni devono avere set di chiavi coerente in `it`, `en`, `eo`.

La verifica pre-rilascio del 26-10-2026 ha controllato focus e ciclo da tastiera nei dialoghi, etichette accessibili dei controlli, movimento ridotto, viewport stretto senza overflow orizzontale, layout genealogico fino a 5.000 persone e i principali confini di sicurezza descritti in `security.md`. La suite unitaria include anche alberi profondi per la validazione e il layout; i risultati della revisione e le verifiche che richiedono hardware fisico sono riportati nella roadmap e nel documento sicurezza.
